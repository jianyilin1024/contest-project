# 部署说明（阿里云）

## 一之二、配置怎么选（学生优惠场景）

| 配置 | 够不够 | 说明 |
|---|---|---|
| **2 核 2G** | ✅ 够（前提：不在服务器上构建镜像） | 全家桶常驻约 1.0–1.2G，本仓库的 compose 已按此调优 |
| **2 核 4G** | ✅ 最舒服 | 可以在服务器上直接构建，不用管镜像仓库 |
| 2 核 1G | ❌ 不够 | PostgreSQL 加应用就满了 |

### 2G 机器怎么跑起来

关键是把 **镜像构建搬到 GitHub Actions**（本仓库已配好 `.github/workflows/build-images.yml`）：

1. 推送到 main 后，Actions 会自动构建 `contest-api` 与 `contest-web` 并推到 `ghcr.io`；
2. 到仓库 **Packages** 里把这两个包的可见性改成 **public**（否则服务器拉取需要登录）；
3. 服务器上 `deploy.sh` 会先 `docker compose pull`，拉到了就完全不构建。

如果暂时不想用镜像仓库，`deploy.sh` 会自动回退到本地构建。此时请确保：

- 初始化脚本已创建 **2G swap**（`init-server.sh` 第 6 步，默认会做）；
- 首次构建前先停掉容器：`docker compose -f docker-compose.prod.yml down`，把内存让给构建；
- 首次构建大约 10–20 分钟，后续因层缓存会快很多。

### 各服务的内存上限（compose 已设定）

| 服务 | 上限 |
|---|---|
| db（PostgreSQL） | 512 MB |
| redis | 96 MB |
| api | 448 MB |
| web | 448 MB |
| nginx | 48 MB |
| **合计** | **1552 MB** |

PostgreSQL 已按小内存调参：`shared_buffers=128MB`、`work_mem=4MB`、`max_connections=50`；
Redis 设了 `maxmemory=64mb` + `allkeys-lru`。

中国大陆服务器必须完成 ICP 备案才能用域名访问：

```
域名实名认证（1–3 天）→ 阿里云初审（1–2 天）→ 管局审核（5–20 天）
```

**如果距答辩不到一个月**，建议：

1. 先买**阿里云香港轻量服务器**（免备案，当天可用）跑起演示环境；
2. 同时用国内节点走备案，作为正式版。

演示当天绝不能赌管局审核进度。

## 二、服务器初始化

在阿里云控制台以 root 登录，执行仓库里的初始化脚本：

```bash
git clone https://github.com/jianyilin1024/contest-project.git /root/contest-project
bash /root/contest-project/infra/scripts/init-server.sh
```

脚本会完成：装 Docker 与 Compose → 设置时区 → 限制 Docker 日志体积 → 创建 `deploy` 用户 → 配置 UFW 防火墙（只放行 22/80/443）→ 创建 2G swap。

> 仓库当前是**私有**的，服务器上需要配置访问凭据，或先用 `scp` 把代码传上去。

### 安全组

阿里云控制台 → 安全组 → 入方向，放行：

| 端口 | 协议 | 用途 |
|---|---|---|
| 22 | TCP | SSH（建议限制为你的 IP） |
| 80 | TCP | HTTP |
| 443 | TCP | HTTPS |

**不要**放行 5432、6379、8000、3000——生产 compose 里没有对外映射这些端口。

## 三、部署代码

```bash
su - deploy
git clone https://github.com/jianyilin1024/contest-project.git ~/contest-project
cd ~/contest-project

cp .env.example .env.prod
vim .env.prod
```

生产环境 `.env.prod` 至少要改这些：

```bash
APP_ENV=prod
DEBUG=false
SECRET_KEY=<随机生成的长串>
POSTGRES_PASSWORD=<强密码>
CORS_ORIGINS=https://your-domain.com
NEXT_PUBLIC_API_BASE_URL=https://your-domain.com
LLM_API_KEY=<你的模型 Key>
```

然后启动：

```bash
bash infra/scripts/deploy.sh
```

或手动：

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
docker compose -f docker-compose.prod.yml ps
```

## 四、域名解析

阿里云 → 云解析 DNS → 添加记录：

| 记录类型 | 主机记录 | 记录值 |
|---|---|---|
| A | `@` | 服务器公网 IP |
| A | `www` | 服务器公网 IP |

验证：

```bash
nslookup your-domain.com
```

## 五、HTTPS 证书

用 Let's Encrypt 免费签发（首次签发需要 80 端口可访问）：

```bash
docker run --rm \
  -v "$PWD/infra/nginx/certs:/etc/letsencrypt" \
  -v "$PWD/infra/nginx/www:/var/www/certbot" \
  certbot/certbot certonly --webroot \
  -w /var/www/certbot -d your-domain.com -d www.your-domain.com \
  --email you@example.com --agree-tos --no-eff-email
```

然后把证书软链到 Nginx 读取的位置，并取消 `infra/nginx/default.conf` 中 HTTPS `server` 段的注释、替换域名，最后：

```bash
docker compose -f docker-compose.prod.yml restart nginx
```

证书 90 天过期，建议加定时任务续期：

```bash
0 3 * * 1 docker run --rm -v /home/deploy/contest-project/infra/nginx/certs:/etc/letsencrypt \
  -v /home/deploy/contest-project/infra/nginx/www:/var/www/certbot \
  certbot/certbot renew --webroot -w /var/www/certbot && \
  docker compose -f /home/deploy/contest-project/docker-compose.prod.yml restart nginx
```

## 六、自动部署（可选）

仓库已包含 `.github/workflows/deploy.yml`：推送到 `main` 后自动 SSH 到服务器执行 `deploy.sh`。

在 GitHub 仓库 **Settings → Secrets and variables → Actions** 添加：

| Secret | 值 |
|---|---|
| `SSH_HOST` | 服务器公网 IP |
| `SSH_USER` | `deploy` |
| `SSH_KEY` | 部署私钥（对应服务器 authorized_keys 里的公钥） |
| `SSH_PORT` | SSH 端口，默认 22，可省略 |

未配置这些 Secret 时，该工作流会自动跳过，不会报错。

## 八、排障

| 现象 | 排查方向 |
|---|---|
| 域名打不开 | 安全组是否放行 80；DNS 是否生效；`docker compose ps` 看 nginx 是否在跑 |
| 502 Bad Gateway | 后端或前端容器挂了：`docker compose logs api` |
| 页面能开但接口 404 | Nginx 的 `/api/` 转发是否生效；后端前缀是否为 `/api/v1` |
| 前端连不上后端 | `NEXT_PUBLIC_API_BASE_URL` 必须是公网域名，且**改完要重新构建** |
| 构建时内存不足 | 已有 2G swap；仍不足可临时加 swap 或改为本地构建后推送镜像 |
| 磁盘满了 | `docker system prune -a`；检查 `backups/` 与 Docker 日志 |
