### 关于「多模态」的现实判断

**不建议强行凑多模态。** 本项目的问题是"文本合并与学术写作"，硬塞图片识别会显得不合逻辑，反而可能拉低"实用性"评分。

如果一定要补，**最自然的一处**是：上传的 docx 里若含**图表**，在合并时保留图片并重新编号（图 1、图 2），并在排版时统一图注格式。这属于"文档结构处理"的自然延伸，而不是生硬的多模态演示。**这只是权宜之计，不建议作为主打。**

## 六、风险提示

1. **提交后不得修改**——若还想加功能（如 MCP、流式输出），必须在提交前完成。
2. **在线演示需评审期间可用**——服务器是 2 核 2G，单实例。若评审集中访问，可能出现排队；建议准备**降级预案**（如截图 + 本地录屏备份）。
3. **API 额度**——DeepSeek 按量计费，评审期间若被频繁调用可能耗尽额度，建议预留余额或设置用量告警。
4. **IP 访问的观感**——用 IP 而非域名，会让"在线演示"看起来不够正式。若时间允许，优先解决备案。
