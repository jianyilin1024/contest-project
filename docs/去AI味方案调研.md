# 「去 AI 味」开源方案调研报告

> 调研时间：2026-10-21
> 调研目的：为本工作台的 AI 生成内容（尤其是 F3 过渡段、归并稿）寻找"去 AI 味"的可借鉴方案
> 结论先行：**这个领域最值钱的东西不是代码，是两份资产——一份 26 条的写作痕迹清单，和一份 283 万字语料的实证研究。**

---

## 一、结论摘要

1. **形态高度集中在"提示词 / Agent Skill"**，而不是算法或模型。Star 数前几名全是 `SKILL.md` + 规则文本，几乎没有可调用的 API。
2. **真正可复用的只有两层**：
   - **规则层**：一份分类清晰的「AI 写作痕迹」清单（blader/humanizer 的 26 条，源自维基百科）；
   - **实证层**：一份用 629 篇对照语料检验了 26 项候选特征的论文（lieflat），**推翻了 15 条流传甚广的错误判断**。
3. **对本项目最关键的一条发现**：我们用的 DeepSeek，在**破折号、提示性冒号、过长前置定语**三项上是五个主流模型里最重的。也就是说，**我们自己的 AI 产出，恰恰是最"AI 味"的那一类**。这直接影响 F3 生成的过渡段质量。
4. **不建议做"过检测器"**。头部项目明确写了"getting past AI detectors is not a goal"，而且实测大多数输出仍会被检测器标出。把这当卖点会翻车。

## 三、关键实证发现（全篇最值钱的部分）

lieflat 用 **629 篇文章 / 283 万汉字 / 9.6 万句**做了对照实验：300 篇由 5 个模型生成，329 篇为人类写作。检验了 26 项"公认的 AI 味特征"。

### 3.1 结果：26 项里只有 11 项站得住

| 通过检验（11 项） | 频率比 R |
|---|---|
| 段首零回指评论 | **4.4** |
| 提示性冒号 / 空转句引列表 | 3.8 / **9.4** |
| 拟人化喻体 | 7.3 |
| 对举结构（不是 A 而是 B） | 3.4 |
| 起首语（说白了） | 3.2 |
| 序数词充当小标题 | 3.1 |
| 破折号 | 3.0 |
| 译文句式（5 种） | 2.6–5.3 |
| 相邻句结构同构 | 2.0 |
| 顿号并列过密 | 1.8 |
| 概括表述覆盖已有数据 | 0.35（反向） |

### 3.2 三条与流行认知**相反**的发现

| 流行说法 | 实测结果 | 启示 |
|---|---|---|
| "AI 爱用比喻包装抽象概念" | **人类用比喻是 AI 的 2.4 倍**；比喻起段是 8 倍 | 问题不在"用不用比喻"，而在**喻体选择**：AI 爱用"像一位智慧的导师"这类理想化人格（R=7.3），人类多用"像我一个做装修的朋友" |
| "AI 爱设问自答" | **正文设问，人类是 AI 的 17 倍** | 按流行建议"删掉设问"，会让文本**更像 AI** |
| "AI 句长太均匀" | 修正切分后 **R=0.87，无差异** | 这条早期得出"51 倍"是切分程序 bug 导致的 |

另外 12 项（句长均匀度、段长均匀度、单字虚词"就"、口语连接词、名词复现、抽象被动、设问自答、问句小标题、句内同构排比、抽象主语、动词名词化、正文序数词）**均无区分力**。

### 3.3 模型差异极大——这条对我们最重要

| 特征（每千字） | Claude | **DeepSeek** | Gemini | GPT | Kimi |
|---|---|---|---|---|---|
| 破折号 | 4.25 | **5.16（最高）** | 0.51 | 0.11 | 2.32 |
| 提示性冒号 | 0.38 | **0.43（最高）** | 0.22 | 0.25 | 0.32 |
| 过长前置定语 | 0.64 | **0.65（最高）** | 0.48 | 0.06 | 0.22 |
| 对举结构 | 0.61 | 0.86 | 0.29 | **1.26** | 0.51 |
| 问句小标题 | 0.043 | 0.086 | **0.173** | 0.008 | 0.000 |

> **解读**：所谓"AI 文风"不是单一形态。破折号在模型间极差达 **47 倍**。
> **我们用的是 DeepSeek 系列 → 破折号、提示性冒号、过长前置定语是三个高优先级靶点。**

### 3.4 方法论上的三个教训（比结论更值得学）

1. **分母选错会得出相反结论**。问句小标题按"每千字"算是 32 倍，按"占小标题总数"算是 0.75（无差异）——前一个分母实际测的是"AI 小标题更多"。
2. **算子必须抽样复核**。作者记录了 6 次因正则过宽导致的测量失误，规程是"采信频率前，先抽检 20 条命中"。
3. **统计显著 ≠ 可执行**。材料密度一项方向明确（人类是 AI 的 2.8 倍），但"补充数据"违反信息守恒，只能保留"不得用概括覆盖已有数据"这一条。

## 四、能直接拿来用的东西

### 4.1 规则清单（26 条，可直接进提示词）

blader/humanizer 的分类结构很好用，按"强度"排序，前 5 条**单次出现就该改**：

| 组 | 内容 | 典型例子 |
|---|---|---|
| **A. 摆架子不说事** | 1 不是 X 而是 Y<br>2 一句话收尾/戏剧化短句<br>3 假深刻的金句<br>4 铺垫后才说正事<br>5 跟空气辩论 | "It's not just X, it's Y"／"让这一点沉淀一下" |
| **B. 按规则制造节奏** | 6 强行三连<br>7 句首重复<br>8 破折号当万能连接符<br>9 限定词堆叠<br>10 到处加连字符<br>11 被动语态缺主语 | "创新、灵感与洞察" |
| **C. 夸大与借权威** | 12 AI 高频词<br>13 夸大意义<br>14 模糊关联<br>15 浅层 -ing 从句<br>16 推销腔<br>17 借来的权威<br>18 回避"是/有" | "delve"／"paving the way"／"专家认为" |
| **D. 按规则排版** | 19 加粗当装饰<br>20 装饰性标题<br>21 弯引号 | "**性能：** 性能提升了" |
| **E. 聊天残留** | 22 客服腔<br>23 知识边界免责<br>24 标题复述<br>25 写文档本身而非主题 | "好问题！希望这有帮助" |
| **F. 写给错的读者** | 26 复述读者已知内容 | 先讲诊断再讲结论 |

### 4.2 可执行算子（有现成 Python 实现）

lieflat 仓库里三个脚本可以直接借鉴：

- `scripts/check-structure.py`：段首零回指评论、相邻句结构同构、比喻起段；
- `scripts/check-translationese.py`：翻译腔标记词表 + 已确认有区分力的 baseline；
- `scripts/compare-human-ai.py`：两侧频率对比。

关键正则（段首零回指评论的判定）：

> 命中「听起来/看起来/说白了/值得注意/问题在于/关键在于…」开头，**且**未命中回指词「这/那/其/此/该/它/因此/但是…」→ 计一次。

修复方法极简单：**补一个指示代词**。这也是全篇最"性价比"的一条改写规则。

### 4.3 四条工程约束（比规则更重要）

| 约束 | 含义 | 出处 |
|---|---|---|
| **白名单原则** | 只处理清单内的特征；未命中的句子**逐字保留**，标题层级/段落次序/列表/表格位置不动 | lieflat |
| **信息守恒** | 不新增姓名、数字、日期、引语、来源、因果；不删观点与限定成分；**不得改变判断强度**（"可能提升"不能改成"提升"） | lieflat |
| **分场景** | 学术/公文/营销/口语的"人味"标准不同，一套规则打天下会坏事 | shuorenhua |
| **展示过程** | 先出第一稿 → 自我批评 → 定稿，让用户看得见改了什么 | blader |

## 五、对本项目的具体建议

### P0：给 F3 过渡段加"去味"后处理（最高优先级）

**理由**：过渡段是我们**唯一 100% 由 AI 生成、且会整段插进学生论文**的内容。它一旦像 AI 写的，整篇论文都会被怀疑。

**做法**：
1. 生成后用本地算子体检三个 DeepSeek 高发特征：**破折号密度、提示性冒号、过长前置定语**；
2. 命中则触发一次"定点改写"（只改命中的句子，其余逐字不动）；
3. 在 UI 上显示"已去味"标记与命中项，让用户知道改了什么。

**成本**：算子是纯本地的（约 100 行 Python），只有命中时才多一次 LLM 调用。

### P0：把"信息守恒"升级为硬校验

现有提示词里已有"不得编造"，但缺两条：
- **不得改变判断强度**（可能 → 会）；
- **不得用概括覆盖已有数据**（这是我们最容易被抓的地方：学生原文有"62.3%"，AI 改写后变成"显著提升"）。

建议做成**事后校验**：改写前后抽取数字/百分比/年份集合，若改写后缺失，直接拒绝该段并回退。

### P1：用学生自己的段落做 voice 样本

blader 支持"给我 2–3 段你自己的文字，我按你的语气改"。**我们已经有这个能力**——单文档 AI 分析里提取的风格画像就是 voice 样本。把这两个功能接起来：归并稿改写时，把该组学生的代表段落作为语气锚点。

### P1：归并稿同样过一遍去味

F1 单文档分析的"生成归并稿"目前只按 canonical_style 改写，没做去味。复用 P0 的后处理即可。

### P2：独立的「AI 味体检」报告

把 11 项通过检验的特征做成一份体检表（每千字频率 + 人类基准 + 命中位置），给用户一个可解释的分数。**注意措辞**：说"写作痕迹"，不说"AI 检测率"。

### P2：diff 式逐句确认

F3 已经有"逐处勾选"的交互，归并稿也应该有"逐句接受/回退"——这正好复用现有 UI 模式。

## 六、不建议做的事

| ❌ 不要 | 原因 |
|---|---|
| 做"过 AI 检测"的卖点 | blader 明确说这不是目标；实测大多数输出仍被标记。承诺了就是给自己挖坑 |
| 用词表黑名单（"值得注意的是""首先"） | 实证显示 15 条流行特征无区分力甚至反向，误删会**降低**文本质量 |
| 强制删除设问、强制加比喻 | 实测人类用这两样**远多于** AI，按流行建议改会越改越假 |
| 把博客/营销的规则套到论文上 | academic-humanizer 明确说：通用 humanizer 跑学术文本会"把精确性一起抹平" |
| 用"降重/洗稿"式改写 | 与学术诚信冲突，且会破坏术语一致性（我们 F4 正在做统一，不能又打散） |

## 七、边界说明（重要）

这批项目的作者们几乎都在 README 里写了同一句话：**这是编辑工具，不是规避检测的工具**。

- 我们的定位应该是"**让 AI 辅助的写作读起来像人写的**"，而不是"**让 AI 写的东西骗过检测器**"；
- 保留 AI 使用记录与 diff，本身就是最好的合规证明；
- 竞赛答辩时这个表态反而加分——它说明我们想清楚了产品边界。
