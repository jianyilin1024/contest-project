# 环境配置说明

本项目所有配置均通过**环境变量**注入，代码中不硬编码任何密钥。

## 一、配置文件分布

| 文件 | 作用 | 是否提交 |
|---|---|---|
| `.env.example`（根目录） | 模板，供 docker compose 使用 | ✅ 提交 |
| `.env`（根目录） | 本地开发实际值 | ❌ 不提交 |
| `apps/api/.env.example` | 后端变量模板 | ✅ 提交 |
| `apps/api/.env` | 后端实际值 | ❌ 不提交 |
| `apps/web/.env.example` | 前端变量模板 | ✅ 提交 |
| `apps/web/.env.local` | 前端实际值 | ❌ 不提交 |
| `.env.prod`（服务器上） | 生产环境变量 | ❌ 不提交 |

`.gitignore` 已排除上述所有实际值文件。

## 二、后端环境变量

配置定义在 `apps/api/app/core/config.py`，由 Pydantic Settings 解析与校验。

### 基础

| 变量 | 默认值 | 说明 |
|---|---|---|
| `APP_NAME` | 参赛项目 API | 服务名 |
| `APP_ENV` | `local` | 可选 `local` / `dev` / `prod` |
| `DEBUG` | `true` | 生产环境务必设为 `false` |
| `SECRET_KEY` | `change-me...` | 生产环境必须换成随机串 |
| `API_V1_PREFIX` | `/api/v1` | 接口前缀 |

生成随机密钥：

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

### 数据库

| 变量 | 默认值 | 说明 |
|---|---|---|
| `POSTGRES_HOST` | `localhost` | 容器内为 `db` |
| `POSTGRES_PORT` | `5432` | |
| `POSTGRES_USER` | `contest` | |
| `POSTGRES_PASSWORD` | `contest` | 生产环境必须修改 |
| `POSTGRES_DB` | `contest` | |
| `DATABASE_URL` | 空 | 填写后优先于上面的分项配置，用于托管数据库 |

> 使用 `DATABASE_URL` 时驱动必须是 `postgresql+asyncpg://`，否则异步引擎会报错。

### Redis

| 变量 | 默认值 | 说明 |
|---|---|---|
| `REDIS_URL` | `redis://localhost:6379/0` | 容器内为 `redis://redis:6379/0` |

### 跨域

| 变量 | 默认值 | 说明 |
|---|---|---|
| `CORS_ORIGINS` | `http://localhost:3000` | 逗号分隔；生产填正式域名 |

⚠️ 前端在浏览器里直接请求后端，**跨域必须配对**，否则首页状态卡片显示红色。
若通过 Nginx 同域代理（`/api` 与 `/` 同一域名），CORS 可保持默认值。

### 大模型

| 变量 | 默认值 | 说明 |
|---|---|---|
| `LLM_PROVIDER` | `openai_compatible` | 目前只注册了这一种 |
| `LLM_API_KEY` | 空 | 必填，否则 AI 功能不可用 |
| `LLM_BASE_URL` | `https://api.deepseek.com/v1` | 各厂商端点见下表 |
| `LLM_MODEL` | `deepseek-chat` | |
| `LLM_TIMEOUT` | `60` | 单次请求超时（秒），长文改写可调大 |

常见厂商配置：

| 厂商 | LLM_BASE_URL | LLM_MODEL 示例 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 阿里通义 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-plus` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |

> 切换厂商**只需改这三个变量**，代码不用动——这是 `app/services/llm/` 抽象层的意义。

### 搜索

| 变量 | 默认值 | 说明 |
|---|---|---|
| `SEARCH_PROVIDER` | `tavily` | 后续阶段接入 |
| `SEARCH_API_KEY` | 空 | 后续阶段接入 |

## 三、前端环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `NEXT_PUBLIC_API_BASE_URL` | `http://localhost:8000` | 浏览器访问后端的地址 |

⚠️ 两个坑：

1. `NEXT_PUBLIC_` 前缀的变量**在构建时写死进前端产物**。生产环境改了地址必须**重新构建**前端镜像，只重启容器无效。
2. 这个地址是**浏览器**去访问的，不能写容器内的 `http://api:8000`（浏览器解析不了 Docker 内部主机名）。生产环境应填写公网域名，如 `https://your-domain.com`。

## 四、端口占用

| 端口 | 用途 | 对外暴露 |
|---|---|---|
| 3000 | 前端 Next.js | 开发环境 |
| 8000 | 后端 FastAPI | 开发环境 |
| 5432 | PostgreSQL | 开发环境；生产不要暴露 |
| 6379 | Redis | 开发环境；生产不要暴露 |
| 80 / 443 | Nginx | 生产环境 |

端口冲突时改根目录 `.env` 里的 `API_PORT`、`WEB_PORT` 等即可。

## 五、常见问题

**首页显示"连接失败"**
1. 后端是否启动：访问 http://localhost:8000/api/v1/health
2. 地址是否正确：`NEXT_PUBLIC_API_BASE_URL` 是否指向后端
3. 跨域是否放行：后端 `CORS_ORIGINS` 是否包含前端地址

**`/health/ready` 返回 degraded**
表示数据库或 Redis 连不上。执行 `docker compose ps` 确认容器状态；本地直接跑后端时，`POSTGRES_HOST` 应为 `localhost` 而不是 `db`。

**修改 `.env` 后不生效**
后端需重启进程；前端 `NEXT_PUBLIC_*` 变量需重新构建。

**数据库想重置**
```bash
docker compose down -v && docker compose up -d
```
